# LLM Anatomy 0.1

[Русский](README.md) | [English](README.en.md) | [简体中文](README.zh-CN.md)

Интерактивный локальный инспектор архитектуры языковых моделей Dense и MoE. Он показывает структуру и тензоры модели, строит интерактивную 3D-карту и оценивает память, не выполняя inference и не отправляя файлы на сервер.

## Требования и запуск

Требуется Node.js 20 или новее.

```bash
npm ci
npm run dev
```

Откройте адрес Vite из терминала (обычно `http://localhost:5173`). Продакшен-сборка и её локальный просмотр:

```bash
npm run build
npm run preview
```

Основные зависимости: React 18, React Flow (`@xyflow/react`) 12, Lucide React и Vite 5. Сеть нужна только для установки npm-зависимостей; уже созданные автономные демо работают без них.

## Возможности

- Локальный импорт GGUF, одного или нескольких SafeTensors и `config.json`, в том числе выбор папки и перетаскивание файлов.
- Вкладки архитектуры, каталога тензоров и оценки памяти; поиск по слоям, именам тензоров и dtype.
- Переключаемые «Анатомия модели» и «3D-карта модели» с детализацией компонентов Dense и MoE.
- Светлая и тёмная темы. Выбор сохраняется в `localStorage` под ключом `llm-anatomy-theme`.
- Русский, английский и упрощённый китайский интерфейс. Язык сохраняется под ключом `llm-anatomy-language` и меняется без повторной загрузки модели.
- Экспорт сводки и метаданных в JSON: React-приложение включает первые 50 000 тензоров, автономная версия — первые 20 000.

## Как пользоваться

1. Нажмите «Открыть модель» для выбора `.gguf`, одного или нескольких `.safetensors` либо `config.json`. Кнопка «Папка» открывает директорию с шардами SafeTensors и необязательным `config.json`, если браузер поддерживает выбор папки.
2. В «Анатомии модели» раскрывайте блоки и слои, перемещайте схему мышью и масштабируйте колесом или элементами React Flow. Вкладка «Тензоры» ищет по имени и dtype, а «Память» оценивает веса, KV-cache FP16 и резерв для запрошенного контекста 2K–128K и batch 1, 2 или 4. Расчёт ограничивает запрос максимальным контекстом, объявленным моделью.
3. В «3D-карте модели» левая кнопка вращает сцену, средняя перемещает, колесо масштабирует, одинарный клик выбирает объект, а двойной открывает компонент. Экранные кнопки управляют масштабом и поворотом; также доступны полный экран, сброс камеры, панели модели/компонентов и симуляция прохода токена со скоростью 0,01×–100×.
4. «Экспорт» сохраняет текущую сводку и метаданные модели в JSON.

## Поддерживаемые форматы и ограничения

- **GGUF v2/v3:** читаются заголовок, metadata KV, имена, типы и размерности тензоров через `File.slice()`. За один импорт обрабатываются первые 32 выбранных GGUF-фрагмента. Если выбрано больше, лишние игнорируются, импорт помечается частичным, а итоговый размер весов и оценка размещения в GPU становятся неизвестными.
- **SafeTensors:** читаются JSON-заголовок, имена, формы и dtype тензоров. За один импорт обрабатываются первые 128 шардов; `config.json` добавляет гиперпараметры модели. Если выбрано больше, лишние игнорируются, импорт помечается частичным, а итоговый размер весов и оценка размещения в GPU становятся неизвестными.
- **Config JSON:** показывает параметры архитектуры без весов. Каталог тензоров пуст, а размер весов и возможность размещения в GPU остаются неизвестными.

Ограничения безопасности парсера: в GGUF допускается до 200 000 тензоров, 300 000 записей метаданных заголовка и размерность тензора не более 8; заголовок SafeTensors — не более 128 MiB. Число слоёв, Q-/KV-голов, экспертов и активных экспертов должно быть целым от 0 до 4096; hidden size — до 1 000 000, FFN size — до 100 000 000, контекст — до 1 000 000 000, словарь — до 10 000 000. Число KV-голов не может превышать число Q-голов, а число активных экспертов — общее число экспертов.

3D-сцена ограничена 12 000 объектами за один показ; открывайте компонент для следующего уровня детализации. У нестандартных архитектур вычислительный граф и MoE-параметры не всегда можно полностью восстановить только по заголовкам. Без `config.json` часть свойств SafeTensors определяется по именам тензоров и может остаться неизвестной.

Оценка VRAM ориентировочная: KV-cache считается в FP16, а фактическое потребление зависит от backend, offload, runtime и настроек. Суммарная память нескольких GPU не равна единому пулу. Реальные маршруты экспертов недоступны без выполнения модели.

## Приватность и безопасность

Разбор выполняется в браузере. Приложение читает только необходимые заголовки и метаданные, не читает значения весов, не запускает inference, не загружает модель на GPU и не отправляет выбранные файлы по сети. `.gitignore` исключает распространённые расширения весов (`.gguf`, `.safetensors`, `.pt`, `.pth`, `.ckpt`), но не обязательно исключает `config.json`, файлы токенизатора/метаданных или экспортированный JSON. Проверяйте такие файлы перед коммитом; не добавляйте модели, секреты или credentials в репозиторий.

## Автономная версия

`standalone/index.html` и `llm-anatomy-demo.html` — прежний 2D-интерфейс без 3D-карты и управления демонстрационным токеном. Их можно открыть через `file://` и выбрать собственный файл модели.

Общие модули парсинга, схемы модели, i18n-сообщений и оценки памяти собираются из `src/`, но интерфейс автономной версии остаётся только русским и не имеет переключателя языка:

```bash
npm run build:standalone
npm run check:standalone
```

Первая команда генерирует `standalone/parser.js` и однофайловый `llm-anatomy-demo.html`; не редактируйте эти два файла вручную. Вторая завершится ошибкой, если они отстали от исходников.

## Проверка изменений

```bash
npm test
npm run check:standalone
npm run build
git diff --check
```

Тесты Node.js проверяют парсеры React- и standalone-версий, валидацию, карту, локализацию, расчёт памяти, симуляцию и публикацию во все remotes. После изменений интерфейса дополнительно проверьте обе темы, три языка, загрузку файлов и основные элементы управления вручную.

## Структура проекта

```text
llm-anatomy/
├── index.html                    # точка входа Vite
├── src/
│   ├── App.jsx                   # дашборд, импорт и 2D-анатомия
│   ├── Universe.jsx              # интерактивная 3D-карта
│   ├── parsers.js                # header-only парсеры GGUF/SafeTensors
│   ├── model-map.js              # иерархия и лимиты 3D-сцены
│   ├── memory.js                 # оценка памяти
│   ├── i18n.js / translations.js # локализация приложения
│   └── styles.css                # темы и адаптивный интерфейс
├── standalone/                   # исходники прежнего интерфейса и сгенерированный парсер
├── scripts/                      # генерация standalone и публикация
├── tests/                        # тесты node:test
└── llm-anatomy-demo.html         # сгенерированное однофайловое демо
```

`dist/` — игнорируемый результат `npm run build`. Источники поведения находятся в `src/`, `standalone/index.html`, `standalone/app.js` и `standalone/styles.css`, а не в сгенерированных файлах.

## Публикация исходников

В текущей конфигурации есть только remote `origin`; наличие GitHub или GitVerse не предполагается. Перед публикацией безопасно проверяйте только имена командой `git remote`, которая не выводит URL с возможными встроенными credentials. Обычный `git push` использует upstream текущей ветки.

```bash
npm run push:all
```

Команда требует выбранную локальную ветку и отправляет её вместе со всеми тегами во все настроенные remotes, начиная с `origin`. После ошибки она продолжает остальные отправки, показывает итог для каждого remote и завершается ненулевым кодом. Она не выполняет force push и не удаляет ветки. Пользовательский HTTPS credential helper работает только с хостами, объявленными в `scripts/git-credential.mjs`; неподдерживаемые хосты завершаются ошибкой без интерактивного запроса. Helper читает токены из внешнего пользовательского файла, путь к которому можно переопределить переменной `LLM_ANATOMY_CREDENTIALS`. Токены не должны находиться в URL remote, документации или исходниках.
