## Замечания

### 1. [P1] Карта неверно связывает компоненты с тензорами

Код: `src/Universe.jsx:14–20`.

Воспроизведение на встроенном Nebula MoE:

- Открыть Embeddings → «Открыть компонент»: список пуст, хотя в модели есть `token_embd.weight`. Фильтр `/embed/` не распознаёт `embd`.
- Attention Norm получает все 10 тензоров слоя, включая FFN/MoE; FFN Norm получает 5 тензоров вместо одного тензора нормализации.
- LM Head получает одновременно `output.weight` и `output_norm.weight`.

На синтетическом SafeTensors-каталоге с раздельными `model.layers.0.mlp.experts.0.*` и `experts.1.*` оба эксперта получают все 6 тензоров: поле `expert` не используется для фильтрации. Имена `transformer.h.0.*` парсер распознаёт как слой, но карта не находит его тензоры, поскольку ищет только `blk` и `layers`.

Последствие: пользователь видит отсутствующие либо чужие веса внутри выбранного объекта.

Исправление: единый разбор имён и индексов слоя/эксперта, отдельные правила для нормализаций, embeddings и выходной проекции. Для объединённых экспертных тензоров показывать общий тензор с указанием среза/ограничения, не представлять его как отдельные веса каждого эксперта.

Подтверждено вызовами функций на демо и синтетических данных; пустой Embeddings также воспроизведён в браузере.

### 2. [P1] Некорректное число слоёв обрушает весь интерфейс

Код: `src/parsers.js:30–35`, `src/Universe.jsx:7–11`, `src/Universe.jsx:24–34`.

Открыть `config.json`:

```json
{"model_type":"llama","num_hidden_layers":1e309,"hidden_size":4096,"num_attention_heads":32}
```

JSON успешно читается, число становится `Infinity`. После перехода в 3D-карту возникает `RangeError: Invalid array length`; в браузере `#root` остаётся без дочерних элементов. Это также происходит при импорте такого файла непосредственно на открытой карте.

Конечные, но очень большие значения тоже принимаются без ограничения: конфигурация со 100 000 слоёв, 128 Q-heads, 128 KV-heads и 128 экспертами потребовала бы 38 900 003 объектов сцены. Такое выделение памяти намеренно не запускалось.

Исправление: проверять конечность, целочисленность и допустимые диапазоны структурных параметров до сохранения модели; вводить бюджет объектов/детализацию сцены и обработку ошибок визуализации.

Подтверждено импортом в Chrome: три события `pageerror`, пустой `#root`.

### 3. [P2] Токен скачет при запуске, возобновлении и выборе объекта

Код: `src/Universe.jsx:47–48`, `src/Universe.jsx:62`.

Эффект устанавливает `previous = 0`, а первый кадр прибавляет к прогрессу `requestAnimationFrame` timestamp целиком. Это время от начала жизни документа, а не интервал между кадрами. Эффект перезапускается при изменении `running`, `selected`, `nodes` и `reset`.

В браузерной проверке после ожидания около 3 секунд первый кадр токена уже выделял Layer 1 → Layer 2 вместо Embeddings → Layer 0. После паузы примерно на 2 секунды возобновление сразу выделило Layer 6 → Layer 7.

Исправление: первый кадр только инициализирует временную отметку; последующие прибавляют разницу. Отдельно определить поведение при смене уровня и возвращении из фоновой вкладки, сохраняя прогресс при обычной паузе и выборе объекта.

### 4. [P2] Большой каталог тензоров вызывает переполнение стека при определении слоёв

Код: `src/parsers.js:29–30`; аналогичный код в `standalone/parser.js:29–30` и однофайловом демо.

При отсутствии числа слоёв в метаданных используется `Math.max(...sampleLayer)`. На массиве из 150 000 записей с корректными именами `model.layers.N.*` это заканчивается `RangeError: Maximum call stack size exceeded`. Контрольный случай на 100 000 записях проходит. Точный порог зависит от JS-движка.

Последствие: большой SafeTensors-каталог без config.json или GGUF без block_count не открывается, хотя число записей укладывается в заявленные ограничения парсера.

Исправление: вычислять максимум циклом/reduce без передачи всего массива аргументами функции.

Подтверждено на Node 20.20.1 прямым вызовом существующей функции восстановления полей модели.

### 5. [P2] Примечание ломает компоновку «Анатомии» на десктопе

Код: `src/App.jsx:81`, `src/App.jsx:127`, `src/styles.css:154`.

`FlowPanel` возвращает Fragment с графом и примечанием. Оба становятся непосредственными flex-элементами `.architecture-layout` рядом с деревом. Правило `> :last-child { flex: 1 }` применяется к примечанию, а не к области графа.

При 1440×900 получены три колонки: дерево 220 px, граф около 479 px, примечание около 115 px. Текст примечания переполняет свою колонку. Скриншот и DOM-измерения подтверждают проблему.

Исправление: обернуть граф и примечание в общую вертикальную колонку, дать ей оставшуюся ширину; примечание расположить под графом.

### 6. [P2] Для config.json планировщик памяти считает размер JSON размером весов

Код: `src/parsers.js:60`, `src/App.jsx:105–106`.

Открыть только config.json с 32 слоями, hidden_size 4096 и 32 головами, затем вкладку «Память». Карточка показывает «Веса на диске: 0 GB», а все три устройства получают положительный статус размещения. В формуле используется `fileSize`, который в этом случае равен размеру JSON (в проверке 89 байт). Размер весов неизвестен.

Последствие: пользователь получает положительный вывод о размещении модели без данных для этого вывода.

Исправление: отдельно хранить известность и размер весов. Для config-only показывать «неизвестно», допускается отдельная оценка KV-cache; итоговый статус размещения не рассчитывать без размера весов или явного пользовательского допущения.

Подтверждено в Chrome импортом config.json и чтением карточек памяти.

### 7. [P2] Мобильное меню нельзя закрыть без выбора раздела

Код: `src/App.jsx:125–126`, `src/styles.css:157`.

При ширине 390 px открыть меню. Оно перекрывает кнопку его открытия; кнопка сворачивания скрыта CSS. Нажатие вне панели и Escape меню не закрывают. Затемнение выполнено через box-shadow, поэтому клик по затемнённой карте попадает в canvas.

Закрыть меню можно только выбором пункта, в том числе уже активного. Такое поведение оставляет пользователя без явного способа отменить открытие и допускает действия на карте под затемнением.

Исправление: доступная кнопка закрытия, настоящий backdrop с обработчиком, Escape и восстановление фокуса на кнопке открытия; не передавать взаимодействия подложке.

Подтверждено в Chrome при 390×844: `.menu-open` сохраняется после клика снаружи и Escape; `elementFromPoint` вне панели возвращает canvas.

### 8. [P2] Рекомендованный README запуск открывает версию без новой карты

Код: `README.md:5–9`, `standalone/app.js:19–20`, `standalone/app.js:67`, `llm-anatomy-demo.html`.

README рекомендует первым способом открыть однофайловое демо и описывает standalone как вариант с теми же функциями. Обе автономные версии по-прежнему имеют меню «Архитектура / Каталог тензоров / Память и VRAM», в них отсутствуют отдельные визуализации, 3D-карта и управление токеном. React-версия существенно отличается.

Исправление: синхронизировать поддерживаемые версии через воспроизводимую генерацию либо явно обозначить автономные версии как прежние демо, а React сделать основным способом запуска актуального приложения.

Подтверждено открытием обоих HTML через `file://` в Chrome.

## Пределы проверки и технические ограничения

- Это ревью текущего состояния, не оценка diff. По нему нельзя определить, какие ошибки существовали до последних изменений.
- Реальные многогигабайтные модели, реальные маршруты инференса, Firefox/Safari и физические мобильные устройства не проверялись.
- Карта использует перспективную проекцию на Canvas 2D. Траектория токена проходит по корневым объектам текущего уровня; это демонстрация, не вычислительный граф и не телеметрия работающей модели.
- Значения весов не читаются. 64 «частицы» тензора — схематические элементы, независимо от его реального размера.
- Сцена целиком пересчитывается и сортируется каждый animation frame, даже на паузе. На демо MoE это 8115 объектов; верхние пределы производительности не измерены. Для роста масштаба понадобятся детализация по расстоянию, ограничение числа видимых объектов и отрисовка по необходимости.
- В package.json нет команд автоматических тестов/линтера. Успешная сборка не заменяет проверок поведения.
